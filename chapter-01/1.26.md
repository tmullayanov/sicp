# expmod with double call instead of square

The version from the book.

```scheme
(define (expmod base exp m)
    (cond ((= 0 exp) 1)
          ((even? exp)
           (remainder (* (expmod base (/ exp 2) m)
                         (expmod base (/ exp 2) m)) m))
          (else (remainder (* base (expmod base (- exp 1) m)) m)))
```


The book asks us to explain Eve's statement that the current version takes $\Theta(n)$ time instead of $\Theta(\log n)$


## Explanation


To analyze the asymptotic time complexity of divide-and-conquer algorithms, we can apply the **Master Theorem**, which addresses recurrence relations of the form:

$$
\begin{equation}
    T(n) = aT\left(\frac{n}{b}\right) + f(n),
\end{equation}
$$
where $a \geq 1$ and $b > 1$.
The asymptotic bound for $T(n)$ is determined by comparing $f(n)$ with $n^{\log_b a}$.

For the original $expmod$ procedure, the running time is governed by the following recurrence relation:
$$
\begin{equation}
    T(n) = T\left(\frac{n}{2}\right) + \Theta(1).
\end{equation}
$$

Here, $a = 1$, $b = 2$, and $f(n) = \Theta(1)$. 
Since $f(n) = \Theta(n^{\log_2 1}) = \Theta(n^0) = \Theta(1)$, this falls under Case 2 of the Master Theorem. Consequently, we obtain the solution:
$$
\begin{equation}
    T(n) = \Theta(\log n).
\end{equation}
$$

In alternative implemenation, due to the fact that `expmod` is called twice when the power gets halved, the recurrence takes slightly different form:

$$
\begin{aligned}
    T(n) = 2T\left(\frac{n}{2}\right) + \Theta(1)
\end{aligned}
$$

Here, $a = 2$, $b = 2$, $f(n) = \Theta(1)$.
The critical function $n^{\log_b a} = n^{\log_2 2} = n^1 = n$

The recursion hre is lift-heavy, it falls under Case 1 of the Master Theorem.
Consequently, we obtain the solution:

$$
\begin{aligned}
T(n) = \Theta(n)
\end{aligned}
$$



## Alternative explanation.

Maybe, SICP doesn't require us to know about Master Theorem in the first place.

When the book discusses orders of growth, it uses more of an intuitive approach.

Why is original `expmod` is $\Theta(\log n)$ in terms of time complexity?
Because each time we double the `exp`, we need to add only one extra `expmod` call. Thus, number of `expmod` calls grows as $\Theta(\log n)$ where $n$ is the `exp` we want to exponentiate the `base` to.

It might be viewed as the reversal of the opposite approach: let's say, we have `k` calls of `expmod`. Those `k` calls allow us to compute `expmod` of $exp = 2^k$.

| View | `expmod` calls | `exp` value |
|------|----------------|-------------|
|`expmod` centric| $k$ | $2^k$ |
|`exp` centric | $\log n$ | $n$ |


Now, back to the implementation presented in the exercise `1.26`.

Let's say that for the arbitrary $exp = n$ the number of `expmod` calls equals to $k$.

Now we'll double $exp$ and see how `expmod` unfolds:

```scheme
(expmod base (* 2 n) m)

(even? (* 2 n)) => #t

=> (remainder (* (expmod base n m)
                 (expmod base n m))
              m)
```

The first call unwinds to make two calls of `(expmod base n m)`, each of which requires us to make $k$ calls of expmod.
Then it means that when we double the argument `exp`, the number of `expmod` calls grows with the same rate as $2*k$, which means that the growth is linear.

(To be more precise, $C(2*n) = 2*C(N) + 1)$, which still evaluates as linear order of growth).
