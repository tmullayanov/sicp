# Difference between applicative and normal eval order

Ben implemented the following test to determine the evaluation order for his interpreter:

```scheme
(define (p) (p))

(define (test x y)
    (if (= x 0)
        0
        y))

(test 0 (p))
```

"What behavior would be observed if the interpreter uses applicative-order evaluation? And what if it uses the normal-order evaluation?"
> note: in both cases `if` is a special operator that evaluates it's predicate first, and only the necessary argument gets evaluated based on that.

`p` is in fact an endless recursion.
The only question is therefore when the (p) actually gets evaluated.

## Applicative-order evaluation

This approach is best described as 'evaluate the operator, evalute the arguments, and then apply the operator'.

The arguments get evaluated as early as possible.

Therefore, `(test 0 (p))` would require the interpreter to evalute `(p)` which evaluates to `(p)` itself.
This process has no end and the evaluation process will be stuck in an endless loop.

Ben wouldn't see the result - the program will be 'stuck' and require manual stop with no result whatsoever.

## Normal-order evaluation

This approach postpones the arguments evaluation until the expression consists only of 'primitive operators'. At this stage, the evaluation goes into 'reduction' stage until it produces the result, following the rules of said primitive operators.

So the substitution will look roughly like this:

```scheme
(test 0 (p)) ; (p) doesn't get evaluated since `test` is not a primitive operator
(if (zero? 0) 0 (p)) ; `if` requires us to have our predicate evaluated first before we touch the arguments
(if #t 0 (p)) ; #t requires `if` to take the first argument, the #f-argument shouldn't be evaluated - (p) still isn't evaluated and won't be.
0
```

In this case Ben would see the result in the form of 0.


## Brief summary

In case interpreter uses applicative-order eval., Ben wouldn't see the result since the program will be run forever.
In case of normal-order eval., the program will end and Ben would see `0`.
